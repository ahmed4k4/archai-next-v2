# Archai — مراجعة شاملة للنظام والداشبورد والحركة والأداء

**التاريخ:** 19 أكتوبر 2026  
**المراجعة:** فحص مصدر ثابت، مراجعة مسارات وCSS وإعدادات SEO، مع فحص حي محدود لصفحة `/en`. هذه ليست شهادة نهائية على بناء الإنتاج أو اختبار حساب Admin فعلي.

## الملخص التنفيذي

طبّقت إصلاحات مستهدفة على الثيمات وحقول لوحة الإدارة، حركة دخول الصفحات من أول فتح، انتقال صفحات الداشبورد، تحميل مجسمات 3D، وخريطة صور المشاريع في sitemap. كما احتفظت بإصلاحات توافق بيانات `project_images` بين المخطط الحديث والقديم التي تعالج خطأي TypeScript السابقين في `admin/seo` و`admin/tools`.

الفحوصات الثابتة ناجحة، لكن لم يمكن تشغيل `next build` أو اختبار تفاعلي فعلي للداشبورد في بيئة التنفيذ الحالية لأن اعتماديات Next/React غير موجودة والاتصال بـ npm registry ينتهي بخطأ DNS `EAI_AGAIN`. لم يتم تنفيذ أي تغييرات مباشرة على قاعدة Supabase المنشورة.

## 1. الداشبورد والثيم والألوان

### إصلاحات منفّذة

- توحيد مظهر حقول الإدخال و`textarea` و`select` داخل `.admin-content`: خلفية ونصّ وحدود وplaceholder واضح، وحالات hover/focus/disabled، مع شكل موحد لخيار القائمة المنسدلة.
- ضبط `color-scheme` صراحةً إلى الداكن/الفاتح حسب `data-theme` حتى لا تظهر عناصر المتصفح الأصلية بخلفية بيضاء ونص غير مقروء.
- الحفاظ على الشريط الجانبي الداكن في الوضعين، مع تثبيت لون النصوص وحالة التنقل النشطة والهوية ومعلومات المستخدم على ألوان ذات تباين واضح.
- تصحيح لون `Workspace` والروابط عند المرور عليها وتوقيع نافذة البحث السريع في الوضع الفاتح؛ كانت بعض الألوان البنفسجية فاتحة أكثر من اللازم على سطح أبيض.
- تحسين ألوان النصوص الدلالية في الوضع الفاتح (`violet`, `mint`, `rose`, `amber`, `blue`) لتبقى الحالات الإيجابية والتحذيرات والأخطاء مقروءة.
- تعديل تدرج صورة الحساب ليستخدم لونًا أخضر أغمق مناسبًا للنص الأبيض.
- إصلاح حالة الثيم في شاشة تسجيل الدخول: تصميم تسجيل الدخول مقصود أن يبقى داكنًا حتى إذا كانت آخر جلسة للإدارة على الوضع الفاتح، لذلك أصبحت ألوانه الداخلية مستقلة عن متغيرات الصفحة العامة.
- تقليل ضبابية وهج تسجيل الدخول على الموبايل وإزالة ضبابية البطاقة في الهاتف لتخفيف الرسم.
- إضافة `MotionConfig reducedMotion="user"` لمكونات الإدارة، وإضافة حركة دخول بسيطة للصفحة الإدارية عند أول عرض وعند تغيير المسار.
- الحفاظ على استثناء البحث من أنماط حقول الإدخال العامة حتى لا تنكسر واجهة البحث السريع.

### أقسام الإدارة التي غطتها مراجعة المصدر

- نظرة عامة / إحصائيات.
- المشاريع والتعديل والحفظ والبحث.
- صور المشروع/مدير الوسائط.
- الأقسام والتصنيفات.
- محتوى الصفحات وإعدادات الرئيسية.
- إعدادات الموقع والهوية والتنقل.
- فحص جودة المحتوى وSEO.
- أدوات الموقع والتحقق من أغلفة المشاريع.
- تسجيل الدخول والتحقق من الجلسة.

لم يتم تسجيل الدخول إلى إنتاج Supabase أو تنفيذ حفظ/حذف فعلي بحساب مدير في هذه الجولة لعدم توفر حساب اختبار. لذلك فالمراجعة لهذه الأجزاء مراجعة مصدر، وليست إقرارًا بأن كل عملية قاعدة بيانات اختُبرت حيًا.

## 2. الحركة والتنقل من أول فتح

- صفحة الموقع العامة تستخدم حركة دخول خفيفة عند أول فتح (`opacity` و`y`) وليس فقط عند تغيير الرابط. الحركة مدتها 340ms ولا تخفي HTML بالكامل أثناء تحميل JavaScript.
- صفحات لوحة الإدارة أصبح لها غلاف دخول مستقل عند أول عرض وعند تغير `pathname`، والحركة تحترم إعداد تقليل الحركة.
- احتفظت بحركة ستارة الانتقال التي تبدأ عند الضغط، وبحدود زمنية تمنع بقاء الغطاء عالقًا.
- لا ينتظر الانتقال اكتمال WebGL؛ المحتوى والـ CSS placeholder يظهران أولًا، والمجسم الحقيقي اختياري من ناحية جاهزية الانتقال.
- تحميل المكونات الثقيلة ما زال كسولًا/ديناميكيًا حيث يلزم، وهو متسق مع إرشادات Next.js لتخفيض JavaScript المطلوب في التحميل الأولي.

## 3. المجسمات ثلاثية الأبعاد والأداء

- يعرض `LazyVisual` شكل CSS احتياطيًا فورًا.
- تبدأ تهيئة المشهد عند اقترابه من مساحة العرض؛ المشهد الظاهر يأخذ أولوية في مسار الانتقال.
- يستخدم طابورًا متسلسلًا لتجنب بدء أكثر من تهيئة WebGL ثقيلة بالتوازي.
- الأجهزة منخفضة الذاكرة/المعالج والأجهزة اللمسية التي لا تجتاز عتبة الموارد تبقى على الرسوم الخفيفة، بينما الأجهزة القوية يمكنها تحسين المشهد تلقائيًا.
- تم الحفاظ على إيقاف حركة مشاهد WebGL غير الظاهرة وتقليل معدل العمل على الهاتف.
- استمرت مكتبات Lenis وGSAP ومكونات البحث الثقيلة في نمط التأجيل/التحميل حسب الحاجة، بدل إضافتها إلى أهم جزء من التحميل الأولي.

هذه تغييرات في المصدر تستهدف أسباب البطء، لكنها لا تعني أن درجة PageSpeed ارتفعت بالفعل؛ لم يتم إنتاج قياس Lighthouse جديد في هذه الجولة.

## 4. SEO والصور

- حدّثت خريطة الموقع `src/app/sitemap.ts` لتستخدم صورة مرتبطة من `project_images` كخيار إضافي عندما تكون حقول الغلاف القديمة (`cover_image`, `featured_image`, `hero_image`) فارغة.
- أبقيت روابط اللغات البديلة `ar`, `en`, و`x-default` في خريطة الموقع.
- احتفظت بمنع فهرسة مسارات الإدارة في `robots` وإعدادات رؤوس استجابة الإدارة.
- يجب التأكد في إعدادات النشر من ضبط `NEXT_PUBLIC_SITE_URL` على الدومين الأساسي المعتمد حتى تتطابق روابط canonical وsitemap معه.

## 5. توافق المخطط والبناء

- `src/app/admin/seo/page.tsx` و`src/app/admin/tools/page.tsx` يضيفان `role: null` إلى السجلات من الاستعلام الاحتياطي القديم عندما لا يحتوي جدول الوسائط على العمود `role`. هذا يعالج خطأ TS2322 الذي أرسله المستخدم.
- ملف إعدادات Next.js الحالي هو `next.config.js` (ولا يوجد `next.config.cjs` موازٍ). وهو يتضمن نمط السماح لصور Supabase العامة.
- خطأ `npm run start` الذي أرسله المستخدم سابقًا كان نتيجة عدم اكتمال `next build`؛ يلزم نجاح بناء الإنتاج قبل تشغيل `next start`.

## 7. ملاحظة من الصفحة المنشورة

عند فحص HTML العام للرئيسية الإنجليزية، ظهر أن مؤشري المشاريع والخبرات في جزء البداية يعرضان `0` بينما قسم أرشيف المشاريع أسفل الصفحة يعرض مشروعًا منشورًا واحدًا. مصدر `AnimatedNumber` الحالي يطبع القيمة الفعلية في HTML الأولي، لذلك بعد نشر هذه النسخة يجب إعادة فحص HTML الفعلي، والتأكد أن Vercel يبني من المصدر الحديث وأن بيانات الإحصاءات والفلترة متسقة.

كما ظهر سجل مشروع بعنوان `5555` ووصف قصير في عرض عام سابق. يجب تغييره أو إلغاء نشره من الداشبورد، والتأكد من وجود صورة غلاف حقيقية قبل اعتبار محتوى الشركة جاهزًا.

## 8. التحقق المطلوب قبل إعلان الإصدار

شغّل محليًا من مجلد المشروع:

```powershell
npm ci
npm run verify:source
npm run typecheck
npm run build
npm run start
```

لا تشغّل `npm run start` إذا فشل البناء. بعد نجاح البناء والنشر:

1. اختبر `/ar`, `/en`, أرشيف المشاريع، تفاصيل المشروع، الخدمات، من نحن، الأقسام، FAQ، التواصل والمقالات.
2. اختبر تسجيل الدخول والخروج، الحفظ، رفع/تعيين غلاف، تحديث الكاش، التبديل بين الثيم واللغة، والبحث السريع.
3. اختبر عرض الموبايل عند 320 و360 و390 و430 و768 بكسل وعلى سطح مكتب.
4. شغّل Lighthouse/PageSpeed على الصفحة الرئيسية وأرشيف المشاريع باللغتين على الهاتف والكمبيوتر، واحتفظ بالتقرير الجديد للمقارنة.
5. راجع مخرجات `npm audit` بالتفصيل. تحذيرات الحزم والتسع ثغرات السابقة لا تعني أنها أصلحت هنا؛ لم يُنفّذ `npm audit fix --force` لأنه قد ينقل الحزم إلى إصدارات رئيسية تكسر التكاملات.
